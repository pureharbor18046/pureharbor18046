# Hey, I'm pureharbor18046

I spend most of my time writing Python scripts that take care of the boring parts of development so I can focus on the interesting ones. Automation is the thread that runs through almost everything I do — from simple shell helpers to larger systems that keep servers and workflows humming without constant babysitting.

## What I work on

- **Python** for everyday tooling, data munging, and glue code between services
- **Automation** that reduces repetitive work, whether it's CI steps, deployment checks, or local environment setup
- **Linux** as my daily driver; I prefer understanding the system rather than fighting it
- **Open Source** contributions and small utilities I publish when they seem useful to others

I like keeping things readable. A script that does one job well and can be understood six months later beats a clever one-liner every time. Most of my projects start as solutions to my own friction points and only later grow into something shareable.

## How I approach problems

When something feels tedious, I ask whether it can be turned into a reliable process. That usually means a bit of Python, some careful logging, and enough tests that I trust the result. I also spend time reading other people's code — the good parts teach better patterns, and the messy parts teach humility.

I prefer tools that stay out of the way. Clear documentation, sensible defaults, and the ability to dig deeper when needed. Linux fits that philosophy for me; so does writing code that other developers (including future me) can pick up without a long onboarding session.

## Outside the terminal

I follow discussions around developer tooling and system design, and I enjoy experimenting with new libraries that make common tasks simpler. If you maintain an open-source project that could use a careful pair of eyes or a small automation improvement, feel free to open an issue or reach out.

Thanks for stopping by.
